# Lap 0.3.2 on Gentoo/OpenRC

This ebuild builds Lap, its Vue frontend, LibRaw, libjpeg-turbo, libheif,
and libde265 from pinned sources. It uses upstream's pinned CPU-only ONNX
Runtime 1.22.0 static binary archive. This is not a completely source-only
build. The supported target is amd64 Linux with glibc.

All build inputs are declared in SRC_URI and checked by Manifest. npm ci
runs offline with install scripts disabled; Cargo also builds offline.
FFmpeg and FFprobe come from media-video/ffmpeg. The self-updater is disabled;
update this installation through Portage.

## Why the AppImage fails

The Lap executable has no direct libsystemd dependency. The 0.3.2 amd64
AppImage bundles an Ubuntu libdbus-1.so.3 whose ELF NEEDED entries include
libsystemd.so.0. The system's Gentoo libdbus-1.so.3 does not need libsystemd.
Building natively avoids the bundled Ubuntu desktop libraries. No Lap
systemd patch, systemd service, or replacement init system is required.

This was verified with readelf -d on the extracted AppImage and ldd on
Gentoo's libdbus-1.so.3. Other system libraries can still depend on systemd
if they were built with that option; normal OpenRC package configuration
is sufficient.

## Install

Enable this overlay and accept the testing keyword if needed:

    # /etc/portage/package.accept_keywords/lap
    media-gfx/lap ~amd64

AI text and image search models are installed by the default ai USE flag.
Face recognition is available with the face flag:

    # /etc/portage/package.use/lap
    media-gfx/lap ai face

The face models have separate non-commercial research-only terms, recorded
in licenses/InsightFace-Models. If those terms suit your use, accept them:

    # /etc/portage/package.license/lap
    media-gfx/lap InsightFace-Models

Then run:

    emerge --ask media-gfx/lap
    lap

Without face, no InsightFace models are installed. Disabling ai omits all
models; the AI code and CPU runtime are still compiled into the application.
Upstream's optional multilingual model download remains available at runtime.

## Refreshing dependencies

The CRATES list and Rust license metadata were generated by pycargoebuild
from src-tauri/Cargo.lock. The npm lockfile patch restores the missing cally
package and synchronizes its root metadata with the 0.3.2 package.json.
Each npm archive is named using the first 16 hex characters of the SHA-256
of its resolved URL; the lockfile integrity values are also checked by npm.
The model URLs use immutable Hugging Face revisions rather than main.

After changing distfiles, run:

    pkgdev manifest media-gfx/lap
    pkgcheck scan media-gfx/lap

Upstream sources: https://github.com/julyx10/lap/tree/v0.3.2
Model terms: https://github.com/deepinsight/insightface/tree/master/python-package

## Validation on this OpenRC system

- Unpack, prepare, and release compilation succeeded with the network sandbox
  enabled and offline Cargo/npm dependency resolution.
- All 13 upstream Rust tests passed.
- Staged installation succeeded with user-owned Portage install settings;
  the live system was not merged or changed.
- readelf and ldd on the resulting executable found no libsystemd dependency
  and no unresolved shared libraries.
- All four ONNX models loaded successfully using the exact packaged runtime.
- Launching with the display disabled reached GTK initialization and failed
  there as expected. Interactive GUI behavior has not been tested.
- pkgcheck scan completed. Existing overlay findings remain; Lap's only
  focused QA finding is Node.js unavailability in the unsupported x32
  development profile.

The staged ai+face installation occupies about 228 MiB. Compilation and
upstream tests used about 5.4 GiB of build space on this system.
